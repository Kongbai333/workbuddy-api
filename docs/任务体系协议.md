## 一、域划分（最容易搞错的地方）

成长中心的接口**分布在两个域上**，混用会得到「路径不存在」类错误：

| 域名 | 用途 |
|---|---|
| `chatBase` = `https://copilot.tencent.com` | 任务列表 / accept / streak / lottery / buddy / travel |
| `webBase` = `https://www.workbuddy.cn` | **任务领奖**（任务码在 URL 路径里） |
| `billingBase` = `https://www.codebuddy.cn` | `/v2/report` 行为上报 |

### ⚠️ 历史事故（真正的坑）

早期实现用 CLI 域调：

```
POST https://copilot.tencent.com/v2/activity/growth/tasks/reward/claim
body: {"task_code": "..."}
```

**该路径并不存在**，恒返回 `400 task not completed` —— 这让「领奖」长期失败，
且错误信息极具误导性（看起来像进度没达标，实际是路径错）。

**正确形态**：

```
POST https://www.workbuddy.cn/activity/growth/tasks/<task_code>/claim
无 body；带 x-client-platform: web 头；Origin/Referer 指向成长中心
```

本项目已在 `growth_test.go` 的 `TestClaimRewardUsesWebDomainPathStyle`
里把正确形态钉死（断言域、路径、方法、头部）。

## 二、接口清单

### 2.1 任务

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v2/activity/growth/tasks` | 全量任务列表（chatBase） |
| POST | `/v2/activity/growth/tasks/accept` | `{"task_codes":[...]}`（chatBase） |
| POST | `/activity/growth/tasks/<code>/claim` | 领奖（**webBase**，任务码在路径） |

**语义要点**：

- `accept` 是「报名」，**不产生进度**。进度由服务端行为事件点亮
  （`chat_request_send` 上报、真实对话等），因此 accept 可安全重放
- `claim` 仅在进度达标后可领；重复领返回 `already_claimed: true`，**不算错误**
- 领奖响应：`{"already_claimed":bool,"credit":n,"energy":n}`

**任务字段**（`data.tasks[]`）：

```
task_code  title  description  task_desc
reward_credit  reward_energy  has_reward  reward_buddy
task_type  tag  jump_url  locked  accept_status  status
progress{current,target}   或平铺的 current/target（两种形态都要兼容）
```

`accept_status` 取值：`not_accepted` / `accepted` / `completed` / `claimed`

**小程序口径**：加 `X-Client-Platform: miniprogram` 头。
小程序专属任务（`Sequential_Tasks_*` / `school_season`）**仅在该口径下发**，
且 accept/claim 同样要求该头（缺头返回 `task not found`）。

> ⚠️ 实测 mp 列表是**默认口径的超集**（含常规任务 + 小程序专属），
> 合并时须按 `task_code` 去重。

### 2.2 连登与抽奖

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/activity/growth/streak` | 连登状态（分组嵌套响应） |
| POST | `/activity/growth/redeem` | `{"tier":"7d","client_token":"..."}` |
| GET | `/activity/growth/lottery/summary` | `{"chances":n,"module":{"enabled":bool}}` |
| POST | `/activity/growth/lottery/draw` | `{"client_token":"..."}` |

- 档位：`7d` / `14d` / `28d`，按**连续登录天数**解锁
- 兑换发放 credit / energy / 补签卡 / **抽奖次数**（抽奖次数只能从兑换获得）
- 未解锁兑换返回 **HTTP 403**「连续登录天数不足」→ 应按状态跳过，别重试
- `client_token` 是前端 `randomUUID` 语义的幂等令牌（8-4-4-4-12 十六进制）

**streak 响应是分组的**（需扁平化）：

```json
{
  "streak": {"days":9,"month_total_days":9,"next_tier":"14d","next_tier_remaining":5},
  "makeup_cards": {"balance":2,"max":3},
  "redemption_status": {
    "tier_7d_status":"redeemable", "tier_14d_status":"locked", "tier_28d_status":"locked",
    "remaining_days":5,
    "tiers":[{"tier":"7d","days":7,"credit":50,"energy":1,"cards":1,"chances":1}]
  }
}
```

### 2.3 猫猫旅行

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/activity/growth/buddy/travel/status` | `state` / `daily_limit_reached` / `record_id` / `reward_credit` |
| POST | `/activity/growth/buddy/travel/depart` | `{"location_id":1..4}` |
| POST | `/activity/growth/buddy/travel/claim` | `{"record_id":n}` → `reward_credit` |

- `state`：`idle` / `traveling` / `arrived`
- `daily_limit_reached`：今日已派出（自然日 00:00 CST 重置）
- `location_id` 实测 1~4，收益与时长区间相同

### 2.4 Buddy（猫档案）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/activity/growth/buddy/info` | `{"buddy":{...}\|null}` |
| POST | `/activity/growth/buddy/agreement` | `{"agree":true}`（幂等） |
| POST | `/activity/growth/buddy/first` | 领养第一只（无猫且过门槛时 +300） |

- `data.buddy` 为 `null` / 缺字段 / 空对象 → **均视为无猫**
  （返回零值 Buddy 会让调用方误以为已有猫而跳过领养）
- 领养门槛未达标 → `400` + 消息含 `first_buddy task not completed yet`
  → **属预期状态，当日静默跳过，不要重试**（避免对上游重试轰炸）

### 2.5 行为上报（本项目基线**已有**）

```
POST {billingBase}/v2/report
body: [ {eventCode:"chat_request_send", conversationId, requestId, ...} ]   // 数组
```

一条 `chat_request_send` 同时点亮 **growth 连登** 与 **解锁领养前置任务**。
**不需要真实对话** —— 纯事件上报。风控口径：每号每天 1 次。

本项目已有实现：`internal/upstream/report.go` 的 `ReportChatActivity`。

## 三、客户端指纹（编排层的关键）

任务计分走 `/v2/report` 行为上报，但**不同任务认不同客户端指纹**：

| 指纹 | 特征 |
|---|---|
| CLI | `www.codebuddy.cn` |
| 桌面 | `copilot.tencent.com` + `WorkBuddy/5.5.6` UA + `workbuddy-desktop` 事件族 |
| web | `www.workbuddy.cn` |
| 小程序 | `X-Client-Platform: miniprogram` |

**这意味着编排层不是纯代码搬运** —— 必须知道「哪个任务对应哪套指纹」。
第三方项目把映射硬编码在 `autotask.go` 的 `autoActions` 表里（约 51 KB）。

本项目为此预留了 `Client.GrowthUA` 字段，由调用方按任务需要设置。

### 未完成部分的注意点

1. **上报原语需泛化**：基线只能发一种硬编码事件
   （`chat_request_send` + 固定模型 `deepseek-v4-flash`）。
   编排层需要任意事件载荷（`chat_message_response`、`agent_task_created`、
   桌面事件族等），必须先把它泛化
2. **调度默认关闭**：新增的定时任务（连登兑换、抽奖、旅行）涉及**真实账号变更**，
   必须做成配置项且**默认关闭**，由用户显式启用
3. **必须实测**：事件伪造的载荷形状是第三方逆向成果，可能随上游变更失效。
   引入前应先用**一个**账号验证「一键完成」是否真能加积分 ——
   自己的账号多半已部分完成过任务，**实际增量需要实测确认**
4. **`Expert_Philanthropy` 不要尝试**：需真实捐款，无法绕过
